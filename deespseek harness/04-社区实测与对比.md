- [金星](https://x.com/btc_great101/status/2088095856318951444) 用 `dsh web + deepseek-v4-pro`，大约 1100 万 token、60 分钟，让它给自己写了个 Tauri 桌面壳。
- HN 用户 mring33621：本地 llama.cpp 跑 9B Qwen 接到 dsh，小 Python 项目很好用，比他试过的别的 harness 快，接本地模型也容易。

**当「能改自己的 Agent」**

- 有人把 Web UI 包成桌面端，或嵌进 VS Code 分栏。

**当「套别的 Agent」**

- Prime Intellect 的 [elie](https://x.com/eliebakouch/status/2087904176357437820) 拆过仓库：dsh 能通过 SDK 拉起 Claude Code / Codex 当子 Agent。四种 mode 本身就是四套小 harness。设计重点：KV cache 前缀尽量不动，历史只追加。这对 DeepSeek 的缓存计价很重要。

[图拉鼎](https://x.com/tualatrix/status/2087895870100664324) 的定位：别拿 dsh 和 Claude / Codex 比成品体验。更像 GNU/Linux 最小系统，后面会出各种发行版。

有人问「官方 dsh 写代码有没有赢过 Claude Code」，底下「我三个都用过，Claude Code 长任务更好」来自推自家 IDE 的账号，口吻很套，**不当实测**。

## 同一只 DeepSeek，换 harness 差多少

这组数是 **V4 Flash + 别人的 harness**，测的是 Gmail / Sheets / GitHub / Slack 多步工作流，**不是官方 dsh**，也不是纯写代码。但能说明 harness 不是皮肤。

来源：[Composio，2026-08-11](https://composio.dev/content/best-agent-harness-deepseek-v4-flash)。30 个任务、同一套 MCP 工具。

| Harness | 通过率 | 中位耗时 | 每次成功成本 |
|---|---|---|---|
| Pi Agent | **66.7%** | 132s | **$0.028** |
| Prime Agent | 62.5%* | 242s | $0.131 |
| OMP | 56.7% | 272s | $0.103 |
| Claude Code | 53.3% | **123s** | $0.195 |
| Codex | 53.3% | 245s | $0.081 |
| DeepAgents | 53.3% | 187s | $0.045 |
| Hermes | 50.0% | 176s | $0.056+ |
| OpenCode | 46.7% | 130s | $0.073 |

他们自己的结论：

- 换 harness 单独就能让 7 个任务过 / 不过翻转
- 成功率差大约 3 题，成本差接近 3 倍，速度差 2.2 倍
- 没有全能冠军：Pi 最会做完、最便宜；Claude Code 最快也最贵

社区经验（dsh 发布前）：

> [adhdsloth](https://x.com/adhdsloth150217/status/2085987466771681482)：别把 DeepSeek 硬接到 Codex / Claude Code。它们系统提示又长又按自家模型写，还经常打爆 cache。Pi、CodeWhale、Reasonix，甚至 Kimi Code，配 DeepSeek 都比 Claude Code 合适。

HN 上也有人写：V4 是在 dsh 上后训练的，所以「V4 + 官方 dsh」理论上比「V4 + 别人的大提示词循环」更贴、更省。这是推断，不是对照实验。

## 和「在别的 harness 里用」差在哪

差的不是「会不会写 for 循环」，是整条执行链。

1. **模型不一定更聪明，循环更对味。** Claude Code / Codex 的提示词、工具约定、压缩是为自家模型焊的。DeepSeek 塞进去能干活，但容易被超长系统提示带偏、cache 命中率掉下去。dsh 反过来：append-only session、前缀尽量不动、极简模式就是评测原教旨。预期是：同样 V4，在 dsh 里更稳、更便宜，不一定在「前端审美 / 长任务管家」上赢 Opus + Claude Code。

2. **编程效果还没有公平对打。** 有的是交付物能交（PPT、桌面壳、改 UI、拼 Bot）、体感快、开箱体验弱于整机。

3. **真正拉开差距的用法，不是当 Claude Code 平替。** X 上做得出来的活几乎都是：改 harness 自己、当插件运行时、包桌面、接本地小模型、需要时再把 Claude Code / Codex 当子 Agent 喊进来。

[宝玉](https://x.com/dotey/status/2087966960386470339) 的概括：Claude Code / Codex 像苹果整机；dsh 像安卓底板。整机今天更好用；底板今天更好改。

## 怎么选（写给以后的自己）

- 日常主力仍是 Claude / GPT → 继续 Claude Code / Codex / Cursor
- 想便宜、快跑 V4，尤其是小改动、修测试、批量活 → 用 dsh 标准模式
- 既要 V4 又要 Claude 收尾 → dsh 里再把 Claude Code / Codex 当子 Agent
- 要自己的工具 / 循环 / 工作台 → 改 dsh，先加工具或 preset，别一上来改内核
