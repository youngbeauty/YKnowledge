# 改它能干嘛，为什么要改

大多数人**不该改它**。开箱当便宜编程工人用就够了。

你要改，只有一种理由：**整机（Claude Code / Codex / Cursor）不让你动的那一层，你正好要动。**

改的不是换皮肤。dsh 把循环、工具、权限、模型、界面都做成插件。改它 = 换零件，不用 fork 整仓。

## 改了能多出来什么

**1. 给你的业务加一只真工具，不是再写一段提示词**

整机里你通常只能加 MCP / Skill：模型「知道」有这个能力。dsh 里可以挂原生工具，进审批、进沙箱、进日志、进回放。

例子：查内部工单、改某张配置表、跑自己的发布脚本、读本机记忆再动手。Cursor 里是「再接一个 MCP，权限和观测随缘」；dsh 里是「和 bash、改文件同一条流水线」。

**2. 换循环本身**

Claude Code 的 loop 你换不了。dsh 里 loop 也是插件。

可以：更激进的压缩、每次改完强制跑测试、失败就开子 Agent、或者极简到只留 bash + 编辑器专门评模型。X 上有人 30 分钟用插件拼出互发消息的 Bot，靠的就是这个。

**3. 同一套壳，换模型、换执行环境**

一只会话里：便宜活走 V4 Flash，难活丢 Claude / Codex 子 Agent；或者接家里 llama.cpp 的 9B。文件系统和 shell 可以一起指到远程沙箱，不用为本地 / 云端 fork 两份产品。

整机基本是：一个产品绑一家模型，最多偷偷换 base URL。

**4. 改产品形态，而不只是改提示词**

社区已经做过：

- session 日志从碍眼按钮改到右键菜单
- 装插件改侧栏（[DSH-better-sidebar](https://github.com/omdsh-dev/DSH-better-sidebar)）
- 包一层桌面端
- 嵌进 VS Code
- 要 Codex 那种跨会话发消息，让它给自己写一个插件

你要交出去的如果是「我们自己的 Agent 工作台」，dsh 是底板。Claude Code 你只能接受它的窗口。

**5. 留下能训练、能审计的轨迹**

模型看见的一切进只追加的 session 日志。回放、分叉、检索都走同一条流。官方自己也拿这套做后训练。你要「每次任务怎么失败的、下次怎么改 harness」，这是设计目标。

整机给你的是产品 transcript，不是你可以当数据集用的事件流。

## 你为什么要改

问自己三句，有一句是真的再改：

1. 我要的能力，MCP / Skill 塞不进去，必须进审批和沙箱。
2. 我要换干活方式（循环、权限、多模型路由、远程沙箱），不是换一句系统提示。
3. 我要交出去的是「我们的 Agent」，不是「我在用 Claude Code」。

否则你会浪费时间。Claude Code / Codex 今天写业务代码更好用。dsh 开箱还薄，预览期还会破兼容。

这三类人改它对：

- **做 Agent 产品的**：要自己的工具、UI、权限，不想从零写 loop
- **DeepSeek 当主力、又在意钱和 cache 的**：V4 按这套壳训过；别人的超长系统提示会打歪、打爆缓存
- **要观测 / 评测 / 后训练的**：极简模式 + 全量轨迹就是为这个准备的

## 和「在 Cursor 里加一条规则」的差别

| 你在 Cursor / Claude Code 里改 | 你在 dsh 里改 |
|---|---|
| 提示词、Skill、MCP | 工具、循环、权限、模型、UI、日志 |
| 产品还是别人的 | 产品可以变成你的 |
| 明天官方一更新，你的技巧可能失效 | 零件你自己装，更新会碎，但碎的是你声明过的接口 |
| 适合把活干完 | 适合把「怎么干活」定义成你的资产 |

## 怎么开始改（别一上来改内核）

1. 先用标准模式跑通一个小仓库。
2. 要加能力：写一个 `apply(ctx)` 工具，`--patch` 挂进去。见 `官方文档/开发-第一个插件.md`。
3. 要换组合：复制一个 preset，或 `dsh plugin --profile web add ...`。
4. 要换循环 / 权限 / 沙箱：再碰对应 seam。架构地图见 `官方文档/架构.md`。

改它不是为了把 Hello World 写得更好。是为了拥有「Agent 怎么干活」这一层。你只是要改业务仓库、修测试、写组件：别改 dsh。
