# 怎么用

先装 Node.js，准备 DeepSeek API Key。第一天对着可丢的 git checkout 试，不要开全盘权限。

## 1. 启动 Web UI

```bash
npx @deepseek-ai/dsh web
```

默认 `http://127.0.0.1:3080`。换端口：

```bash
npx @deepseek-ai/dsh web --port 8080
```

官方 CLI 故意不支持 `--host 0.0.0.0`，只本机听。

npx 第一次会很慢。等不及走源码：

```bash
git clone https://github.com/deepseek-ai/deepseek-harness.git
cd deepseek-harness
pnpm install
pnpm run build
pnpm dsh web
```

看实际装了什么插件：

```bash
npx @deepseek-ai/dsh web --dump-config
```

## 2. 配模型

打开 **设置 → 模型**：

1. DeepSeek 卡片填 API Key，保存。不用重启，下次请求生效。
2. Key 只写一次，页面只看到脱敏引用。实际在 `$DSH_HOME/.credentials.yaml`。
3. 也可「添加提供方」（Anthropic / OpenAI）或「添加自定义提供方」（公司网关、本地 vLLM）。自定义要填：永久小写 Provider ID、base URL、协议、key、至少一个模型 ID。

自定义视觉模型要在 `$DSH_HOME/settings.yaml` 声明 `input: [text, image]`，否则带图会被本地拒掉。DeepSeek 自己的 chat-completions 路由官方写明是纯文本，配置改不了。

排错：

- `MISSING_CREDENTIAL`：key 没存上，或环境变量名对不上
- `UNKNOWN_MODEL`：模型没加进该提供方
- 拉模型列表 401：key 错；对方没有 `GET /models` 就手动填
- Windows 选不了文件夹：换 Chrome / Brave，或走命令行

原文：`官方文档/用户指南-配置模型.md`。

## 3. 选工作区再发任务

Web UI **不会自动选中目录**。点「选择工作区」，加上项目，再选中它。没选中时输入框是灰的。

新会话默认 `workspace-write`：改文件只允许工作区和临时目录；读、网络、看进程不限。更松 / 更紧用 `DSH_PERMISSION_MODE`，或之后在 General settings 改（只影响新会话）。

选 **标准模式**，先只读：

```
先不要改文件。扫一遍这个仓库，告诉我它是什么、主入口在哪、怎么跑测试。
```

看着顺眼再让它改。危险操作会先问你。默认策略 `ask`；CI / 无人值守用 `never`（一律拒绝交互审批）。

## 4. 不要界面

在项目目录里：

```bash
npx @deepseek-ai/dsh --profile headless "run the tests and fix failures"
```

新建持久会话 → 干活 → stdout 打最终回复 → `completed` 退出 0，否则 1。不监听端口。

## 5. Python 里调用

平台：Linux x64/arm64，或 macOS 14+ arm64。内置运行时，不需要系统 Node。

```bash
python -m pip install deepseek-harness-sdk
export DEEPSEEK_API_KEY=sk-...
# 走代理时：
# export DEEPSEEK_BASE_URL=http://127.0.0.1:8000/v1
```

```python
from deepseek_harness import DeepSeekHarness

with DeepSeekHarness(
    provider="deepseek-official",
    model="deepseek-v4-flash",
    cwd="/abs/path/to/workspace",
    session_root="/abs/path/to/sessions",
) as harness:
    result = harness.run(
        "Inspect the repository and fix the failing tests.",
        session_id="example-001",
    )
print(result.final_response)
```

官方 minimal 示例权限是 `danger-full-access`。只在可丢目录或容器里跑。复用同一个 `session_id` 会保留 bash 状态（cwd、环境变量）。新任务换新 id。

原文：`官方文档/用户指南-Python-SDK.md`。

## 6. 接 MCP（可选，默认关）

每个 MCP 服务器是一条独立插件。模型看到的名字是 `mcp__github__create_issue` 这种。

```yaml
- id: mcp-github
  name: '@deepseek-ai/dsh-mcp-client'
  config:
    serverName: github
    transport: stdio
    command: npx
    args: ['-y', '@modelcontextprotocol/server-github']
    env:
      GITHUB_TOKEN: !!js process.env.GITHUB_TOKEN
```

装社区组合包：

```bash
dsh plugin --profile web add github:some-org/some-dsh-plugin
```

插件仓库打 GitHub topic `dsh-plugin`。

## 7. 自己挂一个最小工具

```ts
import type { Context } from '@deepseek-ai/cordis'
import { defineTool } from '@deepseek-ai/dsh-tools'

export const name = 'greet-tool'
export const inject = ['tools']

export function apply(ctx: Context) {
  ctx.tools.register(defineTool({
    name: 'greet',
    description: 'Greet someone by name.',
    parameters: {
      name: { type: 'string', required: true, description: 'The name to greet' },
    },
    output: {
      schema: { type: 'string' },
      render: (_args, value) => [{ type: 'text', text: value }],
    },
    async execute(args) {
      return `Hello, ${args.name}!`
    },
  }))
}
```

源码仓库里用 `pnpm dsh web --patch ./scratch-plugin/cordis.yml` 挂进去。步骤见 `官方文档/开发-第一个插件.md` 和 `官方文档/开发-开发一个工具.md`。

## 现在别怎么用

- 别当稳定生产
- 别第一天对着有密钥的家目录开 `danger-full-access`
- 别指望开箱体验打过 Claude Code（diff、侧栏预览、权限交互都还薄）
- Windows 工作区选择器和「对话中途切模式」社区已经在报 bug
- MCP 默认关是有意的
- 遥测只有你设 `DSH_TELEMETRY_MODE=FULL` 才会往外打
