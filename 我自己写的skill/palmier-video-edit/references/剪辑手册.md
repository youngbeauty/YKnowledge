**中文技术口播 + 屏幕录制**这一类片子怎么剪，全在这一份里。只写怎么做。

## 一、两条铁律

1. **所有改变时长的操作全部做完，再生成字幕。** 剪切点会把跨越它的字幕切碎（294 条 → 632 条）。
2. **`update_text` 改 `content` 会永久清空该条的逐字时间戳。** 之后 `wordReveal` / `highlightPop` / `highlightBlock` 静默失效。

---

## 二、标准顺序

```
1. remove_silence               去静音
2. get_transcript               读词级转录
3. remove_words                 语气词 / 重复字 / 卡壳，一次提交所有索引
   ★ 时长冻结，之后不再动时长
4. add_captions                 字幕唯一一次生成，样式这一步就写进 style
5. 字幕整轨重建                 中文项目必做，见第三节
6. 画面美化                     只做裁剪放大、缩放推进
7. add_texts                    章节卡 / 术语卡，见第四节
8. 首尾淡入淡出                 set_clip_properties，画面和声音成对设置
9. export_project
```

**不做的三件事**：音频降噪（`denoise_audio`）、调色（`apply_color`）、分屏 / 画中画（`apply_layout`）。都不进流程，不用提。

删词必须在第 4 步之前做完——`get_transcript` 和 `remove_words` 直接读音频，不需要字幕轨存在。

第 8 步的「成对」：视频 clip 的音频折叠在 `audio: {id, ...}` 里，给画面设了 fade 声音不会跟着 fade，要用那个嵌套 `id` 再设一次。

### 第 4 步的样式模板

`add_captions` 的 `style` 本身就吃 `background`，白字黑底不用事后补。先问用户要什么样式再生成：

```jsonc
{
  maxWords: 14,          // 中文逐字分词，不放大会碎成两三个字一条
  animation: "fadeIn",
  style: {
    color: "#FFFFFF", bold: true, fontSize: 64, alignment: "center",
    background: { enabled: true, color: "#000000", opacity: 0.85,
                  cornerRadius: 10, padding: { x: 28, y: 14 } },
    shadow: { enabled: true, color: "#000000", blur: 8, opacity: 0.5,
              offset: { x: 0, y: 3 } }
  },
  transform: { centerX: 0.5, centerY: 0.84 }
}
```

有黑底就把 `outline` 关掉，两个一起上会糊。

## 三、中文字幕整轨重建（第 5 步）

本项目固定走本地转录。本地转录逐字分词，字幕必然带满空格（「果 你 的 项 目」），清空格必须重写文字。**不要拿 `canGenerate: false` 建议用户登录订阅。**

超过 10 条要改文字就走这套，**不要逐条 `update_text`**（193 条曾在第 78 条撞上 `Request timed out` + 编辑器卡死）。

### 步骤

```
1. get_timeline captionDetail:true + startFrame/endFrame 分窗口
   → 读出全部 [clipId, startFrame, endFrame, text]

2. manage_tracks remove [{ trackId: 字幕轨 }]
   → 一次删净整轨，返回 removedClipIds 核对数量

3. add_texts entries[]
   → 每条带 content / startFrame / endFrame
   → 超过 ~100 条分批：第 1 批省略 trackIndex（新建轨道，创建后是 index 0），
     第 2 批起每条都写 trackIndex: 0

4. update_text clipIds:[全部 id] + style + transform
   → 一次统一样式

5. get_timeline 回读，核对 totalClips + 抽查文本
```

### 参数

- **窗口大小**：一次返回上限约 50 条。按密度算，`design` 219 条 / 19780 帧用 3800–4400 帧一窗，5 次读完；`wangye` 9015 帧分 4 窗。别开小窗。
- **`add_texts` 每批压到 30 条以内**。响应只列前 30 个 clip（`Showing 30 of 81`），批次超过 30 就拿不全新 id，第 4 步刷样式前还得再 `get_timeline` 分窗把 id 捞一遍——`luna` 为此多花了 4 次读取。30 条一批 = 响应自带全部 id，直接进第 4 步。
- **请求体约 10 KB 会偶发被截断**，报 `could not be parsed as JSON`。81 条 entries 时踩到过一次（另外两批同样大小却过了，所以是偶发不是硬限制）。撞上就拆小重发，不要原样重试。
- **`transform` 必须带 `centerX`**。`get_timeline` 返回时省略了等于默认值的字段（`centerX: 0.5` 被省掉），照抄回去整批会被拒：`transform must be either {centerX, centerY}, or all four`。
- **样式写不写进 entries，看它多大**。219 条各带一份完整 `style`（颜色/字号/底框/阴影/描边）占请求体一大半，那种情况放到第 4 步一次刷完，体积砍约 60%。但如果只有三四个非默认字段（`luna` 第二轮就 `fontSize` + `background.enabled` + `shadow.enabled`），直接写进每条 entry 更好——**一次成型，不用再回读收 clipId，省掉第 4 步和 4 次分窗读取**。
- `captionDetail` 每次会把**其他轨道的全部 clip 一并返回**（`design` 每次多带 186 个），无参数可过滤，忍着。

### 重写 content 时一趟做完三件事

1. **去空格**
2. **修错字**（对照下表）
3. **补回被切点吃掉的首字**——`remove_silence` 的剪切点让转录丢掉每段开头的音节：`在已经是` → 「**现**在已经是」、`马刮目相看` → 「**立**马刮目相看」、`括资源` → 「**包**括资源」、`频开始之前` → 「**视**频开始之前」。音频里那个字在，补回字幕更贴音轨。`wangye` 补 40 余处，`design` 约 20 处。

**只改影响理解的错字。** 平台审查会 OCR 烧进画面的字幕，模型名和厂商名这类词可能过不了——所以**转录把这类词写错时，保留错的，不要"修正"**：

| 转录写成 | 实际是 | 怎么办 |
|---|---|---|
| cloud 模型 / cloudesign | Claude / Claude Design | **保留**，天然规避 |
| 差 GPT / 吉皮提 | ChatGPT / GPT | **保留** |
| 各种谐音、缩写、错拼的模型名和厂商名 | —— | **保留** |

如果转录**正确**写出了模型名，反过来要考虑替换成 `AI 模型` / `大模型` / `模型 A` 或谐音写法，规则同第四节。

其余错字照下表改（音频没错，只改字幕，不要删音频，删了会切坏字音）：

| 错 | 对 | 错 | 对 |
|---|---|---|---|
| 妇科 | 复刻 | 狗皮高腰 | 狗皮膏药 |
| 赵超 | 照抄 | AI 位 | AI 味 |
| 洞校 / 动向 | 动效 | 深图模型 | 生图模型 |
| 附用 | 复用 | 股价图 / 股架 | 骨架图 / 骨架 |
| crom | Chrome | 现稿 | 线稿 |
| 高深 | 黑河 | 世纪软件 | 设计软件 |
| 流水流线 | 流水线 | 见面 | 界面 |
| stich / steach / sties | Stitch | figmar / fig码 | Figma |

**拿不准的专有名词保留原样，不要自己发明**（`design` 的 `replete` / `OGO` / `cloudesign` / `pan` 都留着问用户）。口播本身的重复卡壳（「也不是说也不是说」）照留，音频就是这么说的。

### 重建用户自己调好的字幕：先抄样式，再验样式

用户在界面里调过样式之后才让你去空格，整轨重建会把样式一起删掉。**删轨之前先 `get_timeline` 读 `captionGroups[].shared.textStyle` 和 `.transform`，那就是要复原的全部信息**——`get_timeline` 省略等于默认值的字段，所以列出来的就是全部非默认项，通常只有三四个。

把这几项写进 `add_texts` 每条 entry 的 `style`，重建后回读一条，**比对省略字段的模式跟删之前是否一字不差**。一致就说明渲染结果相同（caption clip 和 text clip 共用同一套 textStyle 默认值，所以这个比对是成立的）。不一致就当场补。

`transform` 记得补 `centerX: 0.5`——原样式里它等于默认被省略了，但 `add_texts` / `update_text` 要求 `{centerX, centerY}` 成对。

### 手册里存的是先例，不是标准

第七节的项目记录是「某次做了什么」的流水，**不要当成规范照抄**。`luna` 第一轮就是照抄了 `design` 的字幕模板（64px / 黑底 0.85 / padding 28×14 / centerY 0.84）和 `Untitled Project34` 的章节卡（白 76px / 居中 / centerY 0.2），用户看了直接否掉——那些数字没有任何依据说明为什么是这个值、跟默认样式比好在哪。

**做视觉决策前先问用户，或者先让他看默认样式。** `add_captions` 不传 `style` 就是默认。抄先例之前至少要知道默认长什么样，否则就是在传播一组没人验证过的数字。

### 动手前告诉用户两个副作用

1. 重建后不再是 caption group，`captionGroupId` 整组换样式的路子没了，改样式要传 `clipIds` 数组。
2. 逐字时间戳彻底没有，只能用 `fadeIn` / `popIn` / `slideUp` 这类整条动画。

### 必查

手打中文极易输错形近字（`wangye` 把「扒下来」打成「扛下来」3 处），而工具照样返回 `changed: true`。第 5 步回读不能省。

**`entries` 里的中文写字面量，不要用 `\uXXXX` 转义**——`workbuddy` 用转义把 `嘛`（U+561B）写成 `嘶`（U+5636），两处，肉眼在请求体里根本看不出来。好在 `add_texts` 响应会回显 `textContent`，逐条比对当场就能抓到。

### 整轨重建顺手合并碎断句

`add_texts` 是按 `startFrame` / `endFrame` 显式建条的，**把相邻几条并成一条只是少写几个 entry，零额外成本**。中文本地转录按停顿切，遇到语速快的口播会碎到 1.3 秒 / 5-6 字一条（`vbc` 6:47 出了 306 条）。既然整轨都要重写，顺手并到 2-3 秒一条：帧区间取并集，批次数也跟着降（306 条 11 批 → 134 条 5 批，撞 MCP 掉线的面小很多）。

被切开的词跨在两条边界上时，把首字挪进前一条，显示时间差不到 0.5 秒，看不出来。

## 三点五、竖屏项目（9:16 / 2160×3840）

### `fontSize` 是相对画布的，不是绝对像素

**别按分辨率去等比换算字号。** `fontSize 48` 在 1920×1080 上单行框高 `0.067`，在 2160×3840 上是 `0.064`——占画面高度的比例几乎一样，编辑器内部按 1080 高做基准自动缩放。

`vbc` 开工时据此推算「48px 在 4K 竖屏只有 1/3.5 大，要放大到 170」，**是错的**，回读几何当场推翻。竖屏项目照常用横屏那套字号即可。

### 窄画布会折行，这才是竖屏真正要算的账

2160 宽比 1920 还窄，但字号按 3840 高缩放，所以**每行能放的字数少很多**：

| 元素 | 单行上限 | 折行后 |
|---|---|---|
| 字幕 48px | 约 9 个中文字（`height 0.064`） | 14-16 字 → 两行 `0.126`；24 字 → 三行 `0.188` |
| 章节卡 76px | 序号 + 5 个中文字（`height 0.099`） | 6 字就折成两行 `0.198` |

贴边红线照旧（下边 ≤ 0.97）：`centerY 0.9` + 两行 `0.126` → 下边 0.963，压线但过；**三行 `0.188` → 0.994，超线**，按 `centerY = 0.96 − height/2` 上移。

所以竖屏合并断句时，14-16 字一条会普遍折两行——这是可接受的（竖屏本来就习惯两行字幕），但**章节卡标题必须压到 5 个字以内**，否则一定折行。

### 加黑底不会改变框高

`update_text` 只传 `style.background.enabled` 时，`transform.height` 原封不动，安全区不用重算。

## 四、章节卡 / 术语卡（第 7 步）

### 违禁词：画面上不出现具体模型名和厂商名

审查会 OCR 画面文字。**凡是烧进画面的字——文字卡和字幕都算——一律不写 `GPT` / `ChatGPT` / `Claude` / `Gemini` 这类具体模型名和厂商名**，用数字或泛称替代：

| 不要写 | 写成 |
|---|---|
| Claude / ChatGPT / GPT-5 | `AI 模型` / `大模型` / `某模型` |
| 对比 Claude 和 GPT | `模型 A` / `模型 B`，或 `① / ②` |
| Claude Code | `AI 编程工具` |

`add_texts` 提交前扫一遍所有 `entries` 的 `content`。字幕侧同理，且转录自带的错拼要保留——见第三节。

### 一条轨道装不下时间重叠的片段

多个文字要**同时**出现在画面上，必须一个占一条轨道。一次 `entries` 全塞同一条轨，后面的顶掉前面的，只剩最后一条，**且不报错**。

| 做法 | 代价 |
|---|---|
| 合成一条字符串（`｜ 引言 ｜ 为什么 ｜ …`，空格控间距） | 1 片段 1 轨道，最省；不能单独高亮当前章节 |
| 每个标签一条轨道 | 能做当前章节高亮（底层灰 + 上层亮）；7 章就是 8 条轨 |

静态章节条用合成字符串，别上多轨。

### 改 fontSize 不会重排 box

`update_text` 只传 `style.fontSize` 时 `transform.width/height` 原封不动——字小了框还那么大。改尺寸**必须显式传 `transform.width` + `transform.height`**。

### 贴边安全区

`transform.height` 是归一化全高占比，box 上下边 = `centerY ± height/2`。**红线：上边 ≥ 0.03，下边 ≤ 0.97**，超了某些播放器会裁掉。

| 元素 | centerY / height | 实际占位 | 1080p |
|---|---|---|---|
| 字幕 64px + padding 14 | 0.84 / 0.135 | 0.7725–0.9075 | 834–980 |
| 字幕 48px | 0.9 / 0.089 | 0.8555–0.9445 | 924–1020 |
| 顶部章节条 28px + padding 6 | 0.065 / 0.052 | 0.039–0.091 | 42–98 |

**底部有字幕时，第二层贴边元素放顶部**（`centerY 0.065`）。底部只剩 0.9075–0.97 这 0.06 的空间，塞不下。

### 折成两行的字幕会捅破下边红线

整轨重建时字数多的那几条会自动折行，`height` 从 0.151 涨到 0.26–0.28。`centerY 0.84` + `height 0.276` → 下边 0.978，**超红线**。

刷完样式回读 `transform.height`，凡是 > 0.24 的单独上移，让下边落在 0.96：`centerY = 0.96 − height/2`（0.276 → 0.822，0.258 → 0.831）。`luna` 243 条里有 3 条。两行的 box 本来就比单行高、视觉上已经在变，上移 0.018 看不出跳动。

## 五、工具表

### 读取 / 状态

| 功能 | 工具 |
|---|---|
| 读时间轴（每会话一次，之后靠 delta 更新） | `get_timeline` |
| 素材库 / 时间轴列表 | `get_media` |
| 转录（词级 / 句级） | `get_transcript` |
| 单素材探查 | `inspect_media` |
| 抓帧存为素材 | `capture_frame` |
| 撤销（全局单步，含用户在界面里的操作） | `undo` |

返回的 delta（`clips` / `shifted` / `removedClipIds` / `createdTracks`）就是最新状态，据此更新模型，别在自己的连续编辑之间重复 `get_timeline`。

### 结构（改时长）

| 功能 | 工具 |
|---|---|
| 放素材 / 嵌套时间轴 | `add_clips` |
| 插入（后续后移） | `insert_clips` |
| 切分 / 删除 / 移动 | `split_clips` / `remove_clips` / `move_clips` |
| 波纹删除区间 | `ripple_delete_ranges` |
| 去静音 | `remove_silence` |
| 按词删除 | `remove_words` |
| 轨道增删排序 | `manage_tracks` |
| 时间轴版本 / 切换 | `create_timeline` / `set_active_timeline` |

### 音频

`detect_beats`、`sync_clips`、`set_clip_properties`（volumeDb / fade）。`denoise_audio` 不用。

### 字幕与文字

`add_captions` 生成字幕、`update_text` 改文字与样式（`clipIds` 收数组）、`add_texts` 文字卡与整轨重建（`entries` 收数组）。

### 画面

`set_clip_properties`（transform / speed / opacity / 圆角）、`set_keyframes`（推进、位移）、`apply_effect`、`change_cam` / `manage_multicam`。`apply_color`、`apply_layout` 不用。

### 生成类

`generate_image` / `generate_video` / `generate_audio` / `upscale_media`——`canGenerate: false` 时会失败，本项目路线不依赖。

### 导出

`set_project_settings`、`export_project`、`manage_exports`

### 习惯

- 汇报一律换成时间码（`帧 ÷ fps`），不甩帧号。
- `undo` 是全局单步，和用户界面操作共享历史栈。撤销前说清撤的是哪一步，不要连续盲撤。
- MCP 会掉线（`Request timed out` 紧接 `Server unavailable`）。**超时那一条状态未知，不要盲目重试**——回读确认，把断点写进暂存盘再告诉用户。
- 改动前先说清副作用，尤其是碎化字幕、清空时间戳、改变时长的。

## 六、做不到的事

| 需求 | 状态 |
|---|---|
| 整体提速 / 变速 | 嵌套时间轴不支持（`nested timelines don't support retiming`）；逐 clip 改 speed 不会波纹闭合，字幕和文字卡不跟随，会全线错位。**导出后用 ffmpeg** |
| 字幕内关键词高亮 | 依赖逐字时间戳，改过文字的做不到。替代：`add_texts` 放术语卡 |
| 看到渲染效果 | `capture_frame` 只存为项目内素材，Agent 读不到图像数据。**必须让用户在预览里确认，不要声称自己看过** |
| 剪完重跑字幕拿干净文本 | 无用，本地转录逐字分词，空格原样复现 |

提速替代方案（`atempo` 保音调；字幕已烧进画面会一起缩放）：

```bash
ffmpeg -i input.mp4 -filter_complex "[0:v]setpts=PTS/1.08[v];[0:a]atempo=1.08[a]" -map "[v]" -map "[a]" -c:v libx264 -crf 18 output.mp4
```

1920×1080 / 30fps。接手时干净：一条 clip，没剪过也没字幕。

| 步骤 | 结果 |

| `remove_silence` | 52 段，−34.3s |
