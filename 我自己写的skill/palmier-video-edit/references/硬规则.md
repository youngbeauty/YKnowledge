# 硬规则

原文是 Palmier Pro 项目库根目录的 `CLAUDE.md`。那个文件夹是 Palmier Pro（AI 视频编辑器）存放所有项目的统一目录。

- `*.palmier/` —— 每个项目是一个 bundle 目录（`project.json` + `media/` + `thumbnail.jpg`）
- `project-registry.json` —— 编辑器维护的已知项目注册表
- 不要直接读写 `.palmier` 内部文件，**一切操作走 Palmier Pro 的 MCP 工具**

在这个目录下工作，默认就是在剪视频。除非用户明确要求别的（写文档、查资料），否则一律使用 Palmier MCP 工具，不要用 shell 或文件工具去动项目数据。

**这份文件只放硬规则。** 操作细节、参数、踩过的坑、各项目改动记录，全部在 [`剪辑手册.md`](./剪辑手册.md)——动手前先读它，不要凭记忆干活。动效素材（Remotion）见 `_motion/README.md`（Remotion 动效工程，不在本 skill 内）。

---

## 开工前必做：先确认是哪个项目

**用户没明确指出项目时，必须先问，不要猜。**

```
1. manage_project action:"list"
2. 如果用户没指名 → 把项目列表给用户，问改哪一个。停下等回答。
3. 确认后 manage_project action:"open"，用 id（不要用名字模糊匹配）
4. get_timeline 一次，把 时长 / 轨道数 / 字幕条数 报给用户核对
5. 核对通过再开始改
```

### 为什么这条是硬要求

`manage_project list` 返回的 `visible` 字段和 MCP 会话实际挂着的项目**可能不是同一个**。曾经发生过：会话挂在一个未注册的项目上，`isActive: false` 但另有项目 `visible: true`，结果 294 条字幕改到了错误的项目上，做了 133 条才发现。

而且注册表里没有的项目照样可能被会话打开——`list` 只列已注册项目，`get_timeline` 却会读当前会话的那一个。**所以永远显式 `open`，永远用 `get_timeline` 的数字跟用户对齐，再动手。**

---

## 两条铁律

1. **所有改变时长的操作全部做完，再生成字幕。** 剪切点会把跨越它的字幕切成碎片（曾 294 条被切成 632 条）。
2. **`update_text` 改 `content` 会永久清空该条的逐字时间戳。** 之后 `wordReveal` / `highlightPop` / `highlightBlock` 全部失效——参数照收，静默不生效。

## 标准顺序

```
1. remove_silence               去静音
2. get_transcript               读词级转录
3. remove_words                 语气词 / 重复字 / 卡壳，一次提交所有索引
   ★ 时长冻结，之后不再动时长
4. add_captions                 字幕唯一一次生成，样式这一步就写进 style
5. 字幕整轨重建                 中文项目必做：去空格 / 修错字，走「三步重建」不要逐条改
6. 画面美化                     只做裁剪放大、缩放推进
7. add_texts                    章节卡 / 术语卡（最后加，避免被剪切点切开）
8. 首尾淡入淡出                 set_clip_properties，画面和声音成对设置
9. export_project
```

**不做的三件事**：音频降噪（`denoise_audio`）、调色（`apply_color`）、分屏 / 画中画（`apply_layout`）。都不进流程，也不用向用户提。

`get_transcript` 和 `remove_words` **直接读音频，不需要字幕轨存在**——所以删词一定要在第 4 步之前做完。

**本项目固定走本地转录，不走订阅。** 不要再拿 `canGenerate: false` 去建议用户登录或订阅——这不是障碍，是既定前提。中文字幕带空格是必然结果，第 5 步的整轨重建就是收尾手段，照做即可，不用每次重新提。

每一步的具体参数和坑：见手册第二、三节。

## 违禁词：画面上不出现模型名

审查会 OCR 画面文字。**烧进画面的字——文字卡和字幕都算——一律不写 `GPT` / `ChatGPT` / `Claude` / `Gemini` 这类具体模型名和厂商名**，用数字或泛称代替：`AI 模型` / `大模型` / `模型 A、模型 B` / `① ②` / `AI 编程工具`。`add_texts` 提交前扫一遍所有 `entries` 的 `content`。

**转录把模型名写错时保留错的，不要"修正"**（`cloud 模型` 实为 Claude、`吉皮提` 实为 GPT）——那是白送的规避。改字幕时只改影响理解的错字，细节见手册第三节。

---

## 批量改字幕：先想清楚走哪条路

`update_text` 的 `content` 一次只吃一条，但 `clipIds` 收数组、`add_texts` 的 `entries` 收数组、`manage_tracks` 能整轨删。

| 要改什么 | 走哪条路 | 调用数 |
|---|---|---|
| 只改**样式**（所有条一样） | `update_text` 传 `captionGroupId` 或 `clipIds` 数组 | 1 |
| 改**文字**，超过 10 条 | 三步整轨重建（手册第三节） | 5+1+3 |
| 只改**零星几条**文字 | 逐条 `update_text` | 每条 1 |

## 工具速查

**读取**：`get_timeline`（每会话一次，之后靠各工具返回的 delta 更新，别反复读）、`get_media`、`get_transcript`、`inspect_media`、`capture_frame`、`undo`

**结构（改时长）**：`add_clips`、`insert_clips`、`split_clips`、`remove_clips`、`move_clips`、`ripple_delete_ranges`、`remove_silence`、`remove_words`、`manage_tracks`、`create_timeline`、`set_active_timeline`

**音频**：`detect_beats`、`sync_clips`、`set_clip_properties`（volumeDb / fade）

**字幕文字**：`add_captions`、`update_text`、`add_texts`

**画面**：`set_clip_properties`（transform / speed / opacity / 圆角）、`set_keyframes`、`apply_effect`、`change_cam` / `manage_multicam` —— `apply_color`、`apply_layout` 不用

**生成类**：`generate_image` / `generate_video` / `generate_audio` / `upscale_media` —— `canGenerate: false` 时调用会失败，本项目路线不依赖它们

**导出**：`set_project_settings`、`export_project`、`manage_exports`

## 已知做不到的事

整体提速/变速、字幕内关键词高亮（改过文字的）、Agent 自己看渲染效果——三件都做不到，替代方案见手册第六节。**视觉效果必须让用户在预览里确认，不要声称自己看过。**

## 工作习惯

- **单位换算**：时间轴位置是项目帧，源素材位置是秒。给用户汇报一律换成时间码（`帧 ÷ fps`），不要甩帧号。
- **`undo` 是全局单步**，且和用户在界面里的操作共享同一个历史栈。要撤销先说清撤的是哪一步，不要连续盲撤。
- **MCP 会掉线**。长循环调用中途可能拿到 `Request timed out`，紧接着 `Server unavailable`（编辑器 App 卡住或退出）。**超时那一条状态未知，不要盲目重试**——回读确认，并把断点和待办写进暂存盘再告诉用户。这也是要少发调用的实际原因。
- **返回的 delta 就是最新状态**，包含 `clips` / `shifted` / `removedClipIds` / `createdTracks`。据此更新自己的模型，不要在自己的连续编辑之间重复 `get_timeline`。
- **改动前先说清副作用**，尤其是会碎化字幕、清空时间戳、改变时长的操作。
- **新学到的东西写进手册，不要写进这份文件**，也不要散在别处。
