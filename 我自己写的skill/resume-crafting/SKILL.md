# 简历包装（Resume Crafting）

目标：把用户真实做过的事，用最高的信号密度呈现出来。**只放大，不虚构**——每一条写上去的内容都必须能在面试中守住 15 分钟的追问，守不住的包装是负资产。

方法论来自一份逐段拆解过的爆火校招简历：手法层拆解见 [references/exemplar.md](references/exemplar.md)（做什么），句式层拆解见 [references/phrasebook.md](references/phrasebook.md)（具体怎么写，13 个句式模板）。开始改写前先读这两份，看看"满分卷"长什么样。

## 工作流程

### 第 1 步：挖料（先问，别急着写）

用户给的初始素材几乎总是不够的。简历写得弱，90% 是因为料没挖出来，不是文笔问题。对每段经历追问：

- **你到底负责到什么程度？** 是 owner、核心成员、还是参与者？从 0 到 1 还是接手维护？（决定能不能用 ownership 语言）
- **有没有数字？** 任何维度都行：性能提升、成本下降、耗时缩短、调用量、用户量、转化率、覆盖率、star 数、榜单名次。用户说"没有数字"时，帮他推算：上线前后对比？人工 vs 自动化耗时？服务了多少人/多少次调用？
- **旧方案是什么，为什么不行，你改成了什么？** 这是"技术判断力叙事"的原料，比"做了什么"值钱得多。
- **有没有外部可验证的锚点？** GitHub 链接、线上产品域名、开源社区身份、比赛名次、内部榜单/等级。
- **有没有极值？** 最年轻的、第一个、排名第一的、唯一的。哪怕限定词很多（"公司内该方向排名第一"）也有效。
- **有什么反差或人味素材？** 跨界背景、非典型起点、小众爱好里做出的东西。

如果用户丢来一份现成简历，先做**逐条诊断**（用下面的手法清单当检查表），标出每条缺什么，再挖料。

### 第 2 步：定信号排序（头部即胜负）

面试官平均 30 秒扫一份简历。前 5 行决定他用什么心态读剩下的部分。

- 把**最稀缺、最可验证**的 2-4 个信号压进姓名下方的一行简介里（年龄/年级优势、开源身份、极值标签、代表作链接）。
- 经历排序按信号强度，不必严格按时间。最硬的一段放最前。
- 每个头部信号都配可点击/可搜索的锚点：少数几个真实可查的锚点会让其余内容集体沾光。

### 第 3 步：逐段改写（统一叙事骨架）

每段经历都套这个结构，读起来像 mini 技术方案而不是岗位描述：

```
项目名 | 一句话定位（借势：绑到大公司/大项目/热方向上）
背景与目标：旧方案的痛点是什么，要解决什么
我的职责：ownership 定位（owner / 核心作者 / 主导 X 到 Y 的升级）
技术链路：具体到架构决策和参数级细节（见"细节密度"手法）
指标：量化收益，用"约 / + / 区间"留余地
```

改写时对照 [references/exemplar.md](references/exemplar.md) 里的手法清单逐条应用，核心的几条：

- **Ownership 语言**：能说"主导/owner/从 0 到 1"就不说"参与/协助"——但必须与第 1 步确认的真实角色一致。
- **演进叙事**：优先写"1.0 有什么问题 → 我改成 2.0 → 收益"，而不是平铺功能列表。
- **热词命名**：把自己做的事映射到行业当前最热的术语上（做上下文裁剪 → Context Engineering；写打分脚本 → LLM-as-Judge / Rubric Eval）。前提：用户真的能讲清这个术语的内涵，否则是自爆按钮。
- **细节密度**：写到参数级（并发数、超时阈值、token 阈值、压缩策略）。具体数字＝可信度，而且密度本身就是威慑。
- **量化留余地**：+25%+、约 30%、月均 600+ 次。区间和约数比精确数字更可信也更难被证伪。

### 第 4 步：防伪审计（最后一道，不可跳过）

逐条过一遍成稿，对每个 claim 问：

1. **面试官追问 3 层，用户能守住吗？**（"这个 25% 怎么测的？baseline 是什么？"）守不住 → 降级措辞或删掉。
2. **数字的口径能说清吗？** 每个数字用户要能一句话说出来源。
3. **热词用户能定义吗？** 让用户口头解释一遍他简历里的每个术语，卡壳的换成平实说法。
4. **ownership 会不会被背调/交叉面试戳穿？** 团队项目里把队友的活写成自己的，是最常见的死法。

把审计中降级/删除的条目告诉用户并说明原因——这本身就是给用户的面试预演。

### 第 5 步：排版交付

文案定稿（或带待确认占位的准定稿）后，用 **resume-typeset** skill 排版导出一页 A4 PDF——那才是最终交付物，markdown 只是中间产物。待确认项在排版里会显示为黄色高亮，视觉上无处可藏。

## 输出格式

- 交付改写后的简历正文（markdown），保持用户原有语言（中文简历就中文，术语可保留英文）。
- 每段改写后附一个简短的「改动说明」：用了哪些手法、哪些数字需要用户确认口径。
- 若用户只给了口头描述，先输出挖料问题清单，拿到回答再写。

## 边界

- 不虚构经历、数字、头衔、身份。用户要求编造时，明确拒绝并解释：包装被戳穿的负收益远大于平淡的负收益。
- 极值标签必须真实成立（可以加限定词收窄范围来让它成立）。
- 这套手法为技术岗（尤其 AI/算法/工程）调校；非技术岗可复用骨架，但热词命名一节要换成对应行业的热词。
