# 08 · 已知限制、风险与商业分发说明

> 本章必须读。尤其是要把这套方案做成付费教程、服务或产品时。

---

## 1. 最大限制：主动推送会话会失效

文本消息虽然允许 `context_token: ""`，但依赖服务端保存的“最近会话”兜底。这个会话不是永久的。

已验证一次真实时间线：

- 22:18 用户主动发消息
- 00:27 推送成功
- 01:22 推送失败
- 08:25 用户再次发消息后立即恢复

能得出的严谨结论只有：

> 主动推送会话可能在数小时后失效，具体时长由微信服务端策略控制，客户端无法保证。

不能宣传：

- “永久推送”
- “永不过期”
- “24 小时稳定主动触达”
- “完全无人值守”
- “100% 到达”

否则属于功能夸大。

---

## 2. 失效后必须由用户主动恢复

收到 `ret=-2: prepare failed` 时，唯一已验证有效的恢复动作是：

1. 用户打开微信
2. 给 ClawBot 发一条任意消息
3. 再次推送

脚本不能代替用户完成这一步。反复请求、刷新 token、改协议版本都没用。

### 对产品体验的影响

如果你卖的是“每天早上 7 点推送”，而用户前一晚很久没有跟 bot 互动，早上可能推送失败；更糟的是，失败消息本身也无法通过同一微信通道通知用户。

因此真正生产化的方案必须有**备用通知通道**：

- 企业微信机器人 webhook
- 邮件
- 短信（付费）
- 飞书 / 钉钉机器人
- App Push

微信 ClawBot 适合作为“轻量提醒通道”，不适合单独承担关键告警。

---

## 3. 头像和昵称不能改

WorkBuddy 客户端与 iLink Bot 协议中没有发现：

- `set_profile`
- `update_bot_info`
- `set_avatar`
- `set_nickname`

已发现的端点只有收消息、发消息、上传、扫码绑定。

因此：

- bot 的头像由平台侧注册决定
- bot 的公开昵称由平台侧决定
- 用户可以在自己的微信里给它改**备注名**，但仅本地可见

想增强辨识度，可以给消息正文统一加前缀：

```text
【久坐提醒】该起来活动一下了
【每日简报】今天有 3 封重要未读邮件
```

---

## 4. 当前脚本只支持纯文本

图片、文件、视频需要额外流程：

1. 获取真实 `context_token`
2. 调 `/ilink/bot/getuploadurl`
3. 上传媒体文件
4. 构造对应类型的 `item_list`
5. 调 `sendmessage`

还可能涉及媒体加密、摘要与文件元信息。本文档未提供可验证的完整媒体实现，不应对外声称支持。

---

## 5. 协议不是公开稳定 API

本方案基于：

- WorkBuddy 桌面端当前实现
- `@tencent-weixin/openclaw-weixin@2.4.6` 的协议行为
- 本机实际请求与响应验证

这不是微信公众平台常规开放 API，服务端可能随时：

- 调整请求头要求
- 升级 `channel_version`
- 修改错误码
- 缩短或改变会话窗口
- 限流
- 下线端点

所以做商业交付时必须写“版本适配”与“维护更新”条款，不要一次卖断后承诺永久可用。

---

## 6. token 安全风险

`botToken` 拥有向当前绑定用户发消息的权限。泄露后第三方可能冒充 bot 推送消息。

### 必须做到

- 脚本从本地配置读取 token，不硬编码
- 文档、演示视频、截图中全部脱敏
- 不上传 `settings.json`
- 不把 token 放入 git、网盘公开链接、AI 在线对话
- 不在前端 JavaScript 或网页源码中使用 token

### 泄露处理

在 WorkBuddy 中解绑并重新绑定微信 ClawBot，使旧 token 失效。

### 多人 / SaaS 场景

不要把多个用户的 token 明文集中存储。至少需要：

- 数据库加密
- 访问控制
- 审计日志
- 密钥轮换
- 用户主动解绑 / 删除能力

本地单用户脚本不等于可以直接扩成 SaaS。

---

## 7. 隐私与数据合规

推送内容会经过微信 iLink 服务。不要未经用户同意推送：

- 身份证号、银行卡号、密码、验证码
- 完整医疗记录
- 公司密级文档
- 第三方个人隐私
- 未经授权的邮件正文

做付费服务时建议：

- 明确告知数据会发送到微信
- 默认只推摘要，不推原文
- 提供内容过滤与脱敏
- 保存最少日志
- 允许用户删除凭据与历史记录

---

## 8. 频率与反骚扰

没有公开的具体限流值，不代表可以高频轰炸。

建议：

- 普通提醒间隔 ≥ 30 分钟
- 相同内容做去重
- 夜间默认静默
- 异常监控只在状态变化时推送
- 提供暂停 / 退订能力
- 不用多个 bot 绕过限制

高频推送可能触发服务端风控或影响用户体验。

## 9. 商业销售建议

### 可以卖什么

- 配置教程与排障知识
- 本地部署 / 安装服务
- 提示词模板与自动化方案
- 多 Agent 集成方法
- 后续版本适配服务
- 备用通道与可靠性增强方案

### 不建议卖什么

- 把腾讯 / 微信 / WorkBuddy 的软件或 token 当成自己的产品转售
- 宣称这是“官方微信主动推送 API”
- 宣称永久、稳定、无限制
- 收集客户完整 `settings.json`
- 给客户内置你的 token

### 对外描述建议

推荐：

> 基于用户已绑定的 WorkBuddy 微信 ClawBot 通道，在本机通过 iLink Bot 协议发送文本通知。适合轻量提醒与任务完成通知；主动会话可能由微信服务端在数小时后关闭，用户需主动给机器人发消息恢复。

避免：

> 破解微信限制，永久免费无限主动群发。

## 10. 版本升级检查项

WorkBuddy 或 openclaw-weixin 升级后，依次检查：

1. `iLink-App-ClientVersion` 是否变化
2. `channel_version` 是否变化
3. 请求头是否新增 / 删除
4. `sendmessage` payload 字段是否变化
5. 成功响应是否仍返回 `message_id`
6. `ret=-2` 恢复方式是否仍有效
7. `settings.json` 配置路径和结构是否变化
8. skill 目录规则是否变化

维护一份真实“验证日期 + 版本号”，比笼统写“长期有效”专业得多。

---

## 11. 适用与不适用场景

### 适合

- 个人轻量提醒
- AI 任务完成通知
- 非关键日报 / 简报
- 本地 Agent 联动
- 技术爱好者自动化

### 不适合

- 安全告警的唯一通知通道
- 支付 / 登录验证码
- 紧急医疗提醒
- 法定送达
- 批量营销群发
- 要求 99.9% 到达率的企业系统

---

## 12. 最终判断

这套方案的价值在于：

- 配置简单
- 零额外服务费
- 直接触达个人微信
- 能被任何本机 Agent 复用
- 对轻量提醒非常实用

它的硬边界是：

- 会话有时效
- 不能保证无人值守长期送达
- 目前只验证文本
- 协议可能变化

把这四点如实告诉客户，才是能长期卖、少售后的做法。
