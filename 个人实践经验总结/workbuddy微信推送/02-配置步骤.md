# 02 · 配置步骤（从零到跑通）

> 全程约 10 分钟。按顺序做，每步都有验证方法。

---

## 步骤 0 · 环境确认

### 0.1 确认 WorkBuddy 已安装

默认安装路径：

```
C:\Users\<你的用户名>\AppData\Local\Programs\WorkBuddy\
```

配置与数据目录：

```
C:\Users\<你的用户名>\.workbuddy\
```

### 0.2 找到 Python 解释器

WorkBuddy 自带 Python，无需另装：

```bash
ls "C:/Users/<你的用户名>/.workbuddy/binaries/python/versions/"
```

会输出版本号，例如 `3.13.12`。完整解释器路径就是：

```
C:/Users/<你的用户名>/.workbuddy/binaries/python/versions/3.13.12/python.exe
```

验证：

```bash
"C:/Users/<你的用户名>/.workbuddy/binaries/python/versions/3.13.12/python.exe" --version
```

> 也可以用系统自带的 Python 3.8+，脚本只用标准库（`urllib`/`json`/`uuid`/`base64`），零依赖。

---

## 步骤 1 · 绑定微信 ClawBot

1. 打开 WorkBuddy 桌面端
2. 进入 **设置 → 连接 / Claw 通道**（不同版本菜单名可能略有差异，找带"微信"字样的入口）
3. 选择「微信 ClawBot」，点击绑定 / 连接
4. 用**你的个人微信**扫码
5. 扫码后微信里会出现一个机器人会话，通常会收到一条欢迎语

### 验证绑定成功

在微信里给这个 bot 发一句「你好」，如果它回复了 → 绑定成功。

⚠️ 如果没回复，检查 WorkBuddy 桌面端是否在运行。**收消息依赖桌面端常驻轮询进程**。

---

## 步骤 2 · 提取通道凭据

绑定成功后，凭据自动写入 `~/.workbuddy/settings.json`。

### 2.1 查看凭据

```bash
"C:/Users/<你的用户名>/.workbuddy/binaries/python/versions/3.13.12/python.exe" -c "
import json, os
p = os.path.expanduser('~/.workbuddy/settings.json')
s = json.load(open(p, encoding='utf-8-sig'))
for uid, u in s.get('claw', {}).get('users', {}).items():
    ch = u.get('channels', {}).get('weixinClawBot')
    if ch:
        print(json.dumps(ch, ensure_ascii=False, indent=2))
"
```

### 2.2 你会看到

```json
{
  "enabled": true,
  "channelId": "d2cc68bff868@im.bot",
  "botToken": "d2cc68bff868@im.bot:0600002xxxxxxxxxxxxxxxxxxxxxxxxxxx",
  "baseUrl": "https://ilinkai.weixin.qq.com",
  "accountId": "d2cc68bff868@im.bot",
  "userId": "o9cq80-EXAMPLE_USER_ID@im.wechat",
  "connectionMode": "polling"
}
```

### 2.3 字段说明

| 字段 | 作用 | 备注 |
|---|---|---|
| `enabled` | 通道是否启用 | 必须为 `true` |
| `botToken` | 认证凭据 | ⭐ **必须含 `accountId:` 前缀** |
| `baseUrl` | API 域名 | 固定 `https://ilinkai.weixin.qq.com` |
| `userId` | 你的微信标识 | 消息的 `to_user_id` |
| `accountId` | bot 账号 | 用于定位 cursor 文件 |
| `connectionMode` | 连接模式 | `polling` = 长轮询 |

### 2.4 如果没输出

说明 `weixinClawBot` 节点不存在或 `enabled` 为 false。回到步骤 1 重新绑定。

也可能是配置结构不同（版本差异），用这个命令把整个 claw 节点打出来看：

```bash
"C:/.../python.exe" -c "
import json,os
s=json.load(open(os.path.expanduser('~/.workbuddy/settings.json'),encoding='utf-8-sig'))
print(json.dumps(s.get('claw',{}),ensure_ascii=False,indent=2)[:3000])
"
```

## 步骤 3 · 安装推送脚本

### 3.1 创建目录

```bash
mkdir -p "C:/Users/<你的用户名>/.workbuddy/skills/wechat-push"
```

### 3.2 写入脚本

把 [04-脚本与技能包.md](04-脚本与技能包.md) 中的 `send_wechat.py` 完整源码保存为：

```
C:/Users/<你的用户名>/.workbuddy/skills/wechat-push/send_wechat.py
```

**注意**：脚本运行时自动读 `settings.json`，**不需要**在脚本里填任何 token。换绑账号后脚本自动跟随，无需修改。

### 3.3 写入技能说明（可选，但推荐）

同目录下保存 `SKILL.md`（内容见 `04` 文档）。有了它，WorkBuddy / Codex / Claude Code 会自动识别这个能力，你说"发到我微信"它就知道该调什么。

## 步骤 4 · 激活推送会话

⭐ **这一步是整套方案最关键、也最容易被忽略的一步。**

**在微信里给 ClawBot 发一条任意消息**（"在吗"、"1"、随便什么都行）。

### 为什么必须做

微信不允许 bot 单方面主动推送。必须有"用户最近说过话"这个证据，服务端才放行。这个证据就是 `context_token` 的兜底会话。

不做这一步，第一次推送就会返回 `ret=-2: prepare failed`。

### 有效期

约**数小时**（实测本机 22:18 激活 → 01:22 失效，约 3 小时）。具体时长由微信服务端策略控制，客户端无法延长。

失效后重新发一条消息即可恢复，立即生效。

---

## 步骤 5 · 首次推送验证

```bash
"C:/Users/<你的用户名>/.workbuddy/binaries/python/versions/3.13.12/python.exe" \
  "C:/Users/<你的用户名>/.workbuddy/skills/wechat-push/send_wechat.py" \
  "配置成功，这是第一条主动推送"
```

### 成功

```
[weixinclaw] OK 消息已发送, message_id=7491156072188354056
```

微信立刻收到消息 → **配置完成** 🎉

### 失败

对照 [07-故障排查.md](07-故障排查.md)，两个最常见的：

| 错误 | 原因 | 解决 |
|---|---|---|
| `ret=-2: prepare failed` | 会话未激活或已失效 | 回步骤 4，微信发条消息 |
| `errcode=-14 session timeout` | token 不完整或请求头缺失 | 检查 botToken 是否含 `accountId:` 前缀 |

## 完整配置检查清单

全部打勾 = 配置完成。

## 安全提醒

`botToken` 是敏感凭据。**不要**：

- 提交到 git 仓库
- 粘贴到聊天群、论坛、issue
- 写死在会被分发的脚本里（本方案从配置文件读，就是为了避免这点）
- 截图时露出完整 token

如果泄露：在 WorkBuddy 里解绑 ClawBot 后重新绑定，旧 token 即失效。
